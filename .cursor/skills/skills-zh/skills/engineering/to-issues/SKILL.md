# 转换为问题

使用垂直切片（示踪弹）将计划分解为可独立获取的问题。

问题跟踪器和分类标签词汇应该已经提供给你——如果没有，运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

从对话上下文中已有的内容开始工作。如果用户传递问题引用（问题编号、URL 或路径）作为参数，从问题跟踪器中获取它并读取其完整正文和评论。

### 2. 探索代码库（可选）

如果你尚未探索代码库，请这样做以了解代码的当前状态。问题标题和描述应使用项目的领域词汇表词汇，并尊重你正在接触的区域中的 ADR。

### 3. 起草垂直切片

将计划分解为**示踪弹**问题。每个问题是一个薄的垂直切片，端到端地穿过所有集成层，而不是某一层的水平切片。

切片可以是"HITL"或"AFK"。HITL 切片需要人工交互，例如架构决策或设计审查。AFK 切片可以在没有人工交互的情况下实现和合并。在可能的情况下优先选择 AFK 而不是 HITL。

<vertical-slice-rules>
- 每个切片通过每一层（模式、API、UI、测试）提供狭窄但完整的路径
- 完成的切片可以单独演示或验证
- 优先选择许多薄切片而不是少数厚切片
</vertical-slice-rules>

### 4. 询问用户

将提议的分解呈现为编号列表。对于每个切片，显示：

- **标题**：简短的描述性名称
- **类型**：HITL / AFK
- **被阻塞**：哪些其他切片（如果有）必须首先完成
- **涵盖的用户故事**：这解决了哪些用户故事（如果源材料有它们）

问用户：

- 粒度感觉对吗？（太粗/太细）
- 依赖关系正确吗？
- 是否应该合并或进一步拆分任何切片？
- 正确的切片是否标记为 HITL 和 AFK？

迭代直到用户批准分解。

### 5. 将问题发布到问题跟踪器

对于每个批准的切片，将新问题发布到问题跟踪器。使用下面的问题正文模板。这些问题被认为已准备好供 AFK 代理使用，因此除非另有指示，否则使用正确的分类标签发布它们。

按依赖顺序发布问题（先阻塞者），以便你可以在"被阻塞"字段中引用真实的问题标识符。

<issue-template>
## 父级

对问题跟踪器上父问题的引用（如果源是现有问题，否则省略此部分）。

## 要构建什么

这个垂直切片的简洁描述。描述端到端的行为，而不是逐层实现。

避免特定的文件路径或代码片段——它们很快就会过时。例外：如果原型产生的片段比散文更精确地编码决策（状态机、reducer、模式、类型形状），在此内联并简要说明它来自原型。修剪到决策丰富的部分——不是工作演示，只是重要的部分。
